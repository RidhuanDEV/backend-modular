# Deployment
One HTTP and one email-worker process per container; one-shot migrate runs before them. Seed is profile explicit. Non-root UID10001, writable uploads volume, UTC, graceful30s shutdown, JVM memory70%, container HTTP8080 and selected APP_PORT host mapping. Use provider compose file; no fixed container names.
Profiles redis/s3/telemetry are optional. S3 bucket must exist; development MinIO init creates it. Redis remains mandatory for shared quota with APP_INSTANCE_COUNT>1. APP_INSTANCE_COUNT is env, not auto-detection.
S3_PREFIX is the deployment-owned namespace within the bucket. The CLI derives it from the deployment identity; set a unique value for independent applications sharing a bucket, and keep it stable on redeployments. Cleanup only traverses canonical UUID keys in this prefix. Changing it requires moving existing objects explicitly; it is not a data migration.
Spring/Micrometer owns telemetry. Do not add OTel auto-agent. OTEL_ENABLED defaults false; OTEL_EXPORTER_OTLP_ENDPOINT is HTTP/protobuf trace endpoint with /v1/traces. Sampling is configurable. Exporter failure does not affect readiness. Collector resource limit and batch bound are in scripts/otel-collector.yaml.
Actuator management endpoints are not publicly exposed. /live is HTTP process; /ready tests DB and required Redis, ignoring SMTP/S3/cache-only/collector. No schema mutation on health requests.
SMTP STARTTLS and implicit TLS use JavaMail trusted CA and hostname checking. Add CA to JVM truststore outside the template. Disable TLS only for isolated development fixtures. Rotate secrets by env/redeployment; existing refresh-family state survives migrations.
Ingress must be authenticated/trusted and TLS configured independently. Forwarded headers are disabled by default. Production load, failover, external TLS, backups and disaster recovery require deployment-specific verification.
