# Verification stages
All scenario scripts and fixtures must be authored before running a stage. Complete implementation first, full build with test execution disabled, collect build failures, then unit/static/runtime/consumer/Compose gates. Independent tasks keep logs/exit status and aggregate FAILED on any failure or cleanup error. Dependent API scenario may stop at a broken prerequisite.
scripts/verify-stage.ps1 collects unit/format/source gates. In the root create-ridhuan-backend package, scripts/run-springboot-stage.mjs collects manual, Compose, consumer and package tasks; scripts/verify-springboot-runtime.mjs contains the complete provider API scenarios. All logs/fixture data live under OS temp. scripts/verify-springboot-consumer.mjs covers tarball installation and native generator; CLI_RUNTIME_TEST=true adds real native provider migration and generated-module HTTP CRUD. Root CI supplies Windows/Linux consumers, macOS smoke and Compose provider jobs.
Owned Docker names carry a unique project prefix. Cleanup always runs in finally and verifies containers/volumes/networks/images absent. No global prune. Rerun affected gates before complete stage, bounded repair attempts and diagnostic root-cause grouping.
Current evidence is documented in docs/VERIFICATION.md after execution; unchecked gates are not proof. Build/health/unit checks do not establish production scale.
